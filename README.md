# Предсказание iPhone / Android методом KNN

Пользователь отвечает на 21 вопрос. Приложение сравнивает его ответы с участниками исходного опроса, находит пять наиболее похожих и предсказывает класс телефона: **iPhone** или **Android**.

Сайт показывает предсказание, доли голосов классов, ближайших соседей и расстояния до них. Также доступны метрики модели и оценка влияния каждого вопроса. Базы данных, регистрации и внешнего API нет. Отправленные ответы не сохраняются.

## Установка и запуск

Нужен Python 3.11+ и зависимости из `requirements.txt`. Для нового окружения проще использовать Python 3.11 или 3.12; в текущем окружении проект также проверен на Python 3.14.7.

```bash
python -m venv .venv
source .venv/bin/activate
# В Windows вместо предыдущей команды: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/train_model.py
uvicorn app.main:app --host 0.0.0.0 --port 8742 --reload
```

Открыть в браузере: **http://127.0.0.1:8742**. Если виртуальное окружение уже создано, достаточно активировать его и запустить последние две команды. Готовая модель есть в `artifacts/`, поэтому для первого запуска сайта обучение можно пропустить. После изменения CSV или признаков модель нужно обучить заново и перезапустить сервер: он держит загруженную модель в памяти.

## Что происходит при обучении

1. `load_frame()` читает CSV. Время заполнения исключается. Ответы становятся таблицей **X**, известные телефоны — массивом **y**. Телефон не входит в X: иначе модель получила бы правильный ответ на входе.
2. Вопросы получают короткие имена `q1`…`q21` по порядку CSV. Эти же имена использует форма.
3. `train_test_split()` делит данные: 80% на обучение и 20% на проверку. `stratify=y` сохраняет примерно одинаковые доли классов. `random_state=42` делает разделение воспроизводимым.
4. `build_pipeline()` собирает подготовку признаков и KNN в одну последовательность — **Pipeline**. `fit()` обучает её только на тренировочной части.
5. Предсказания для тестовой части сравниваются с известными телефонами. Отдельно рассчитывается влияние вопросов.
6. Модель и метрики записываются в `artifacts/`. Веб-сервер загружает готовый результат.

### Зачем обрабатывать ответы

KNN вычисляет расстояния между числовыми наборами признаков. Строки вроде «Да» нужно сначала превратить в числа.

| Ответ | Обработка | Зачем |
| --- | --- | --- |
| Категории: «Да», «Нет», «Не знаю» | One-hot: отдельный столбец 0/1 на каждый вариант | Не задавать ложный порядок между вариантами |
| Сфера деятельности (`q15`) | Такой же one-hot | Считаем написанные строки категориями; анализа смысла текста нет |
| Возраст, бюджет, частота, оценки 1–10 | Пропуск → медиана, затем StandardScaler | Привести числовые признаки к сопоставимому масштабу |
| Несколько вариантов (`q4`) | Пять столбцов 0/1 | Сохранить каждый выбранный вариант |

Например, «Статус;Камера» превращается в `[1, 1, 0, 0, 0]`. Пятый вариант «Мультивыбор» встречается в старом CSV: он сохранён в модели, но не предлагается в форме как причина покупки.

`SimpleImputer` заполняет пропуски. `StandardScaler` для каждого числового столбца вычитает среднее и делит на стандартное отклонение. Без него разница бюджета в 30 000 рублей могла бы перекрыть разницу возраста в 5 лет. Среднее, медиана и масштабы берутся **только из тренировочной части** и сохраняются для новых ответов.

`ColumnTransformer` применяет нужную обработку к каждой группе столбцов. `Pipeline` объединяет её с классификатором, чтобы при обучении и на сайте использовалась одинаковая подготовка. Неизвестная категория кодируется нулями (`handle_unknown="ignore"`); сайт не падает из-за новой сферы деятельности.

## Как получается предсказание

```text
Форма → app.js → POST /api/predict → проверка ответов
      → таблица из одной строки → сохранённая обработка
      → пять ближайших соседей → результат JSON → показ в браузере
```

KNN (k-nearest neighbors, «k ближайших соседей») хранит обработанные тренировочные примеры. Для нового человека вычисляется евклидово расстояние:

```text
расстояние = √(сумма квадратов разностей соответствующих признаков)
```

Берутся **k = 5** ближайших участников. Каждый голосует за свой известный класс телефона. `weights="distance"` означает: чем меньше расстояние, тем больше вес голоса (обратно пропорциональный расстоянию). При точном совпадении sklearn учитывает голоса соседей с нулевым расстоянием. Побеждает класс с большей суммой весов.

Например, сумма весов Android равна 3, iPhone — 1. Доли голосов: Android 75%, iPhone 25%. Победит Android, даже если простое количество соседей другого класса больше.

«Уверенность» на странице — доля взвешенных голосов победившего класса. Это **не гарантия правильности** и не проверенная вероятность будущей покупки. Расстояния показаны в пространстве обработанных признаков, а не в рублях или годах. Сам выбор k=5 задан в коде; автоматического поиска лучшего k в проекте нет.

## Что означают метрики

- **Accuracy (точность)** — доля правильно предсказанных телефонов в тестовой части.
- **Precision** класса — сколько предсказаний этого класса оказались верными.
- **Recall** класса — какую долю настоящих представителей класса модель нашла.
- **F1** — показатель, объединяющий precision и recall. **F1 macro** — среднее F1 двух классов с одинаковым весом.
- **Матрица ошибок** — строки соответствуют настоящим классам, столбцы — предсказанным. Порядок классов записан в `metrics.json` в `labels`.

В исходном CSV 41 участник: 32 для обучения и 9 для теста. При проверке текущего алгоритма accuracy равна 7/9 ≈ 77,8%, F1 macro — 0,75. На таком маленьком тесте один ответ сильно меняет точность; эти цифры описывают конкретное разделение данных.

### Почему оценок влияния две

**Связь с классом (`association`)** показывает, насколько ответы связаны с известным телефоном в данных. Для категорий используется V Крамера с поправкой на число вариантов; для чисел — модуль корреляции с меткой iPhone=1, Android=0. Большая связь не доказывает причинность. На странице коэффициент умножается на 100: это не процент правильно предсказанных ответов.

**Влияние на KNN (`permutation_importance`)**: перемешиваем ответы одного вопроса между участниками, остальные ответы сохраняем, снова считаем точность. Если она падает, модель использовала информацию этого вопроса. Повторяем 40 раз и сохраняем среднее падение и его разброс. Для q4 перемешиваем все пять столбцов вместе, чтобы сохранить сочетания вариантов.

Оценка может быть отрицательной: после перемешивания точность случайно выросла. В JSON это значение сохраняется. Для показанных долей «KNN» отрицательные значения заменяются нулями, положительные делятся на их сумму. Ширина полос нормируется отдельно относительно максимальной оценки.

Влияние вопросов рассчитывается **по всей выборке**, включая тренировочную часть, как в исходной версии проекта. Поэтому оно объясняет поведение модели на этих данных, но не является независимой оценкой качества. Accuracy и F1 рассчитываются отдельно на тестовой части.

## Адреса сервера

| Метод и адрес | Что делает |
| --- | --- |
| `GET /` | Показывает форму и сохранённые метрики |
| `GET /api/metrics` | Возвращает метрики в JSON |
| `POST /api/predict` | Принимает `{"answers": {"q1": "Стабильность", …}}`; нужно заполнить все 21 поле |
| `POST /predict` | Старый адрес: возвращает 410 и подсказку использовать JSON API |
| `GET /static/...` | Отдаёт JavaScript и CSS |

В JSON q4 — список строк, например `["Статус", "Камера"]`; числовые ответы могут быть числами или строками с числом. Сервер проверяет заполнение полей, наличие выбора q4, конечность чисел и заданные границы. Проверка не ограничивает все категории перечнем формы; незнакомые категории допускает обработчик модели.

Ошибки: 400 — неправильный JSON, 422 — неправильные ответы, 503 — нет модели, 500 — ошибка предсказания. Если модель отсутствует, главная страница показывает команду обучения.

## Короткое объяснение для защиты

«Мы сделали веб-опрос, который предсказывает класс телефона по предпочтениям пользователя. Данные — ответы 41 участника. Мы исключаем время и телефон из входных признаков, кодируем категории, приводим числа к сопоставимому масштабу и обучаем KNN на 80% данных. Для нового пользователя модель находит пять похожих участников; ближайшие имеют больший вес голоса. Качество проверяем на остальных 20%. Браузер отвечает за форму, FastAPI — за запросы, scikit-learn — за обработку данных и предсказание».

Типичные вопросы:

- **Почему KNN?** Его решение легко объяснить через похожих участников, и для небольшой таблицы он прост в реализации.
- **В чём обучение, если KNN хранит примеры?** Обучаются параметры подготовки данных; классификатор сохраняет подготовленные примеры для поиска соседей.
- **Зачем отдельный тест?** Проверить ответы, которые модель не использовала при обучении.
- **Почему обработка хранится вместе с моделью?** Новые ответы должны кодироваться и масштабироваться так же, как тренировочные.
- **Какие ограничения?** Мало участников, чувствительность к выбору данных, масштабу признаков и k. Предсказание отражает закономерности этого опроса. Вопросы сохранены из исходного CSV, их полезность не гарантирована.
- **Что можно улучшить дальше?** Собрать больше ответов, нормализовать написание профессий, подбирать k на кросс-валидации и оценивать влияние на отдельной проверочной выборке.
